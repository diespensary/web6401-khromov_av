# ЛР №3

## Задача
Реализовать набор функций на JavaScript без сторонних библиотек:
- `isInteger(n)` — проверить целое число с использованием побитовых операторов.
- `even()` — вернуть массив четных чисел от 2 до 20 включительно.
- `sumTo(n)` — посчитать сумму `1..n` циклом.
- `recSumTo(n)` — посчитать сумму `1..n` рекурсией.
- `factorial(n)` — вычислить `n!`.
- `isBinary(n)` — проверить, является ли `n` степенью двойки.
- `fibonacci(n)` — найти `n`-е число Фибоначчи.
- `getOperationFn(initialValue, operatorFn)` — вернуть функцию‑аккумулятор операции через замыкание.
- `sequence(start=0, step=1)` — создать генератор арифметической последовательности.
- `deepEqual(a, b)` — выполнить глубокое сравнение по содержимому (без учета специальных типов вроде Date/RegExp).

## Что сделано
- `isInteger` — использовано побитовое ИЛИ с нулем: `(n | 0) === n`, с защитой от не‑чисел.
- `even` — сформирован статический массив `[2,4,...,20]` в цикле с шагом `2`.
- `sumTo` — линейный цикл с аккумулятором.
- `recSumTo` — базовый случай `n===1`, рекурсивное сложение `n + recSumTo(n-1)`.
- `factorial` — итеративное умножение, поддержка `0! = 1`.
- `isBinary` — проверка `n > 0` и `(n & (n - 1)) === 0`.
- `fibonacci` — итеративно, O(n) по времени, O(1) по памяти.
- `getOperationFn` — замыкание со `storedValue`; без `operatorFn` всегда возвращает `initialValue`.
- `sequence` — независимые генераторы; по вызову отдают текущее значение и сдвигают на `step`.
- `deepEqual` — сравнение примитивов, `NaN≈NaN`, объектов по ключам и значений рекурсивно; функции по `toString()`.

# ЛР №4

## Задача
1.	Вёрстка с помощью Flexbox – 1 страница.
2.	Вёрстка с помощью Grid – 1 страница.
3.	Задание всех цветов только с помощью переменных в CSS.
4.	Реализация анимации (красивой!) с помощью CSS – 1шт.
5.	Реализация страницы с формой, включающей не менее 3 различных типов полей (например, страница авторизации с вводом логина, пароля и галочкой-согласием на обработку данных) и кнопку отправки данных на сервер.
6.	Создание класса, содержащего конструктор и метод форматированного вывода на консоль. При нажатии на кнопку отправки данных на сервер должен создаваться объект, хранящий введённые данные, после чего вызывается метод вывода на консоль.
7.	Бонус: использовать методологию БЭМ

## Что сделано
1. Вёрстка с помощью Flexbox - 1 страница
- **Страница**: `signup.html` (форма регистрации)
- **Контейнер**: `.signup` с `display: flex`
- **Элементы**: `.signup-intro` и `.signup-form-card` адаптивно располагаются в строку/колонку
- **Адаптив**: На мобильных экранах переходит в колонку

2. Вёрстка с помощью Grid - 1 страница
- **Страница**: `index.html` (главная)
- **Два Grid-контейнера**:
    - `.hero` (2 колонки: текст + изображение)
    - `.cards` (3 колонки карточек)
- **Адаптив**: На узких экранах переходят в 1 колонку

3. CSS-переменные для цветов
- В `styles.css` создана секция `:root` с 11 переменными
- Все цвета задаются через `var(--имя-переменной)`
- Единая палитра для всего сайта

4. CSS-анимация
- **Анимация**: `@keyframes float` для `.hero-img`
- **Эффект**: "Плавающая" печать с вращением
- **Длительность**: 6 секунд, бесконечный цикл
- **Учёт доступности**: `@media (prefers-reduced-motion)` отключает анимацию

5. Форма с разными полями
- **Страница**: `signup.html`
- **Типы полей**:
    - `text` (имя)
    - `email` (почта)
    - `select` (уровень прокрастинации)
    - `time` (пиковое время)
    - `textarea` (комментарий)
    - `checkbox` (согласие)
- **Валидация**: HTML5-атрибуты `required`
- **Кнопка отправки**: С градиентом и hover-эффектами

6. Класс JavaScript
- **Класс**: `ProcrastinationApplication` в `app.js`
- **Конструктор**: Принимает все данные формы
- **Метод**: `printToConsole()` форматированно выводит объект в консоль
- **Интеграция**: Срабатывает при отправке формы

# ЛР №5

## Задача
1.	Динамическая проверка данных формы в процессе ввода с использованием событийной модели JavaScript и вывод текстовых подсказок для пользователя.
2.	Реализация отправки данных формы после её валидации на сервер через POST-запрос (без обработки на серверной стороне).
3.	Реализация асинхронного запроса на сервер для получения данных (например, для заполнения одной из таблиц) с обязательной обработкой возможных ошибок.
4.	Организация асинхронного получения данных таким образом, чтобы оно выполнялось периодически (например, раз в 5 минут).

В качестве реализации серверной части использовать https://github.com/ajoelp/mock-json-server (JSON-файл с данными также разместить в папке c проектом).

## Что сделано
1. Динамическая проверка формы:

- Валидация в реальном времени при вводе
- Подсказки под полями с ошибками
- Визуальное выделение невалидных полей

2. Отправка POST-запроса на сервер:

- Отправка данных формы на http://localhost:3000/applications
- Обработка успешной отправки и ошибок
- Сообщения пользователю о статусе отправки

3. Асинхронное получение данных:

- Загрузка расписания с сервера (http://localhost:3000/schedule)
- Динамическое заполнение таблицы
- Обработка ошибок сети и сервера

4. Периодическое обновление:

- Автоматическое обновление расписания каждые 5 минут
- Индикаторы загрузки
- Сообщения об успешном обновлении

Все функции работают асинхронно с использованием Fetch API и обрабатывают возможные ошибки сети.

## Запуск
1. npm install -g json-server
2. json-server --watch db.json --port 3000
